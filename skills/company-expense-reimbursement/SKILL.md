# 公司差旅报销

用户发送发票、出差资料，或要求整理报销时使用本 skill。普通同事只需用自然语言提出请求，不要求其打开 PowerShell 或运行脚本。使用本机已保存的邮箱凭据和本地人员/公司配置；绝不要求用户在聊天中粘贴密码。

## 自然语言入口

“扫描我这次出差的企业邮箱并整理报销单”表示可以读取本次出差日期范围内的邮箱。先做只读扫描，再下载候选附件；报告邮件数、附件数、下载数、重复数和未解决问题。PDF 或图片必须交给 `$mineru-pdf-to-md` 解析。

## 必须执行的流程

1. 读取 `references/company-policy.md`、`references/local-profile.md`、`references/hotel-standard.md` 和 `references/mail-ingest.md`。身份信息只能来自本地配置。
2. 对每份 PDF/图片调用 `$mineru-pdf-to-md`，保留源文件名和页码。MinerU 结果异常时可用 PDF 文本层交叉检查，但要保留 MinerU 文件并标记人工复核。
3. 用 `scripts/new_workbook.py` 生成每次独立的报销工作簿，模板由 `scripts/build_template.py` 在运行时构建。第一张纸面数据表固定 6 行；超过 6 行时追加同版式第二页，不拉长第一页。
4. 直接使用 XLSX 纸面表，在 WPS 中导出 PDF 校验。纸表本体参考实物的宽表比例，页面设置为 A4 纵向、单页、居中；用户未要求时不生成 HTML，也不发送打印任务。
   - 6条明细后直接接“合计金额（大写）”，不额外打印数字合计行。标签靠左，“￥：”位于整行约 71% 宽度处；仅保留实物中附注列向下延续的边界。出差补助逐行金额、补助小计和大写金额数值保持空白，由财务填写。
5. `发票明细` 每份来源文件占一行；纸面报销行必须能通过来源索引追溯到原始文件。
6. 不从文件名、开票日期或示例图猜测出发地、到达地、入住日期、离店日期或金额。缺失就留空并报告。
7. 公司名称、税号、地址、电话、开户行、账号与发票不一致时立即提出，禁止静默改写。

## 业务规则

- 住宿发票必须有入住和离店日期，缺任一项就标记“待补充入住/离店时间”，不能当作完整凭证。
- A 到 B 的出差当天发生连续住宿，住宿费写在 A 到 B 行；B 地有多张住宿票时按日期从上到下分行。
- 路线必须闭环。末点不回到起点时标记“路线未闭环”，指出缺少的行程，禁止虚构返程。
- 第一条行程必须单独核对方向和交通方式。示例：`公司→示例城市 示例项目` 的第一条行程必须核对去程方向与所用交通方式。
- 纸面表“车船费”的“名称”栏只能填 **`车票`、`机票`、`船票`** 三者之一，不得写入车次、航班号、路线、席别、“公司车自驾”或任何其他文字。具体车次、航班、承运方、席别与路线只写在“发票明细”和校验报告中，不写进纸面报销单。无法归入上述三类时留空并列入待人工确认事项。
- 纸面表中的日期必须写完整日期或完整的“月日”，不得只写数字日号。表头“出差起止日期”必须完整可见。
- “出差补助”金额和对应小计由财务填写；生成工作簿时逐行补助金额及该列小计必须留空，不得计入自动合计。
- “合计金额（大写）”由财务手工填写，生成工作簿时金额栏保持空白；“附单据”只统计正式报销单据，辅助结账单不重复计数。
- 已有工作簿可调用 `scripts/fill_total.py workbook.xlsx` 检查非补助费用小计；脚本不得写入或覆盖财务填写的补助金额和大写合计。
- 报销单附注只解释特殊情况；没有特殊情况时留空。普通发票索引、来源文件和路线校验结论分别保存在“发票明细”和校验报告中，不自动写进纸面报销单。
- 住宿、火车、机票等需要打印 2 份；其他单据打印 1 份。住宿结账单只作辅助凭证，不打印，不重复计入金额。
- 行程单是否打印，由电子发票本身是否带行程说明决定：先检查发票正文是否同时含"出行日期／乘车日期""出发地""到达地"（铁路电子客票的出发站到达站、网约车发票的出行日期与出发地到达地都算）。三者齐备时发票已能独立证明行程，**行程单不打印、不重复计入**；缺任一项时才随发票一并打印行程单作为补充说明。判断结果要写进校验报告。
- 打印包排版：一张 A4 放两张同尺寸发票（上下排列，默认 `--sheet 2up`）。发票自带的大片空白必须先按内容边界裁掉，再摆放；内容从左上角起排，**禁止横向或纵向自动居中**。页码/日期标注落在发票之外的留白条带，不得与发票任何内容重合。具体冻结参数见下方"打印策略（已冻结）"。
- 签名栏保持空白，打印后手写。

## 打印策略（已冻结，2026-10-14 经实打验收）

以下参数是用户逐项验收后固定的，**不要再逐次试错调整**：

| 项目 | 冻结值 | 原因 |
|---|---|---|
| 每张 A4 | 2 张发票（上下排列） | 用户要求；放不下时自动降为 1 张/页 |
| 包内留白 | **28pt（≈9.9mm）** | 发票最外侧的表格框线贴到内容边界，实测留白 17pt（≈6mm）时右侧外框线被打印机裁掉；28pt 后落纸约 9.1mm，安全 |
| 页码标注位置 | 落在发票下方 14pt 留白带内；**右端内缩 40pt** | 右对齐标注止于 6mm 时落纸约 5.6mm，同样被裁 |
| 居中 | **从不居中**（左上起排） | 居中会让后续裁剪难以对位 |
| 机器相关参数 | **不引入** | 换打印机不应改参数 |

### 报销联 / 抵扣联（两套独立编号）

- **报销联**：全部发票，按**时间线**（出行/入离日期）编号 `第1/N页`；
- **抵扣联**：只数**可抵扣发票**（有税额的增值税发票；铁路票与住宿专票计入，**网约车/出租车客运票不计入**），独立编号 `第1/M页`，M 通常小于 N；
- 同一张发票的两联**同页**：报销联在上、抵扣联在下；
- 份数规则由此推出：住宿/火车/机票 = 2 份（报销联+抵扣联）；滴滴等 = 1 份（仅报销联）。

### 打印执行（仅在用户明确同意后）

1. 自审：`python scripts/check_packet.py <packet.pdf>`，内容距纸边须 ≥4.5mm、左右差 ≤4mm、标注齐全，**不通过则不得交付或打印**；
2. 渲染：把每页按 A4 宽度渲染成 600dpi 位图（宽 4760px）；
3. 送打：.NET `PrintDocument`，`PaperSize` 必须**按 DPI 折算成 1/100 英寸**（`px / dpi * 100`）。直接把像素数当英寸会打出 47×70cm 的巨幅页；
4. 绘制：`DrawImage` 于 `(0,0)`，目标框＝整页，**不居中、不平移、不二次缩放**；
5. 送打宽度 196mm 左右（略小于驱动自报的可打印宽；驱动自报值通常偏大，直接采用会被裁边）。


## 发票打印包

各类发票统一用 `scripts/print_invoice_packet.py` 生成打印包：

```powershell
python scripts/print_invoice_packet.py <文件|目录|通配符> ... --output "05-报销/发票打印包.pdf" --kind taxi
```

铁路电子客票用封装好的 `scripts/print_rail_packet.py`（等价于 `--kind train`）：

```powershell
python scripts/print_rail_packet.py <发票.pdf|发票.ofd|下载的.zip|目录> ... --output "05-报销/铁路发票打印包.pdf"
```

滴滴/网约车发票用封装好的 `scripts/print_taxi_packet.py`（等价于 `--kind taxi --copies 1`）：

```powershell
python scripts/print_taxi_packet.py <发票.pdf|目录|通配符> ... --output-dir "05-报销" --name "滴滴发票打印包.pdf"
```

住宿发票用封装好的 `scripts/print_hotel_packet.py`（等价于 `--kind hotel`，每张 2 份）：

```powershell
python scripts/print_hotel_packet.py <发票.pdf|目录> ... --output-dir "05-报销" --name "住宿发票打印包.pdf"
```

两个票种入口都以通用脚本 `print_invoice_packet.py` 为内核，共用下列固定约定，不再需要逐次调参：

- 一张 A4 放两张同尺寸发票（上下排列）；内容放不下或缩到不可读时自动降为一张一页；
- 每张发票先裁到内容边界，四边留白对称（默认 10pt），标注日期/页码落在发票下方的留白条带，绝不与发票重合；
- 内容从左上起排，**任何情况下不自动居中**；
- 不写任何打印机专属偏移或缩放，最终缩放交给打印机的"适合页面"，换机器无需改参数；
- OFD 自动取其中的同号 PDF；标注日期优先取发票上的乘车/出行日期（铁路票读 OFD 内的 TravelDate），绝不使用开票日期；
- 生成前自动检查箱体：部分厂商发票的 CropBox 超出 MediaBox（例如 MediaBox 595×842 而 CropBox 宽 610、起点 y=-22），标准阅读器取交集后会**静默裁掉左侧二维码和右侧发票号码**。脚本会自动把 MediaBox/CropBox 重写为覆盖内容的矩形，并说明已修正；**源文件不改动**。因此不要用"把留白调大"来掩盖这类缺角。

打印由用户在可见桌面上用系统自动打印完成。

## 行程单取舍（按发票内容自动判断）

生成打印包时先检查每张电子发票是否自带行程说明：

- 发票正文同时出现"出行日期／乘车日期"、"出发地"、"到达地"（铁路票为出发站／到达站）→ 发票可独立证明行程，**行程单不打印**，并在输出中说明被剔除的文件；
- 缺任一项 → 随发票打印对应行程单作为补充说明，并计入校验报告。

判断由脚本自动完成（`print_packet.prune_supplements`）：发票正文含出行/乘车日期与起止地点时，行程单不再打印，并在输出中说明被剔除的文件。

## 模板和视觉自检

模板源文件必须以 UTF-8 保存。每次生成后必须：

1. 用 `openpyxl` 重新打开工作簿，核对工作表名称、合并单元格、字段坐标和填充值；模板字段和填充脚本的坐标不一致时停止输出。
2. 检查所有文本不包含 `?`、乱码替代字符或未经授权的品牌文字。
3. 使用实物的白底蓝字表头；日期列必须能在一行显示“9月28日”，不得因列窄拆行。日期值、第一行方向和交通方式均非空。“车船费”名称栏的值必须属于 `车票`、`机票`、`船票`，且不得超出列宽被裁切。
4. 用 WPS 将报销单工作表导出为 PDF（单页时可用 `scripts/export_wps_pdf.py`），再渲染为图片进行视觉检查。核对 A4 纵向单页、日期与交通方式无裁切、各列比例、合并表头、线色及“￥：”位置。签字栏在表格外，不添加框线。导出 PDF 不等于实际打印。
5. 视觉检查失败时继续修改模板并重新生成，不能把未检查的工作簿交给用户。
6. 打印包生成后必须核对：每张 A4 的发票张数、发票内容是否被缩放裁切、页码标注是否完全落在发票之外的空白处、四边留白是否对称。任一不满足时重新生成，不得直接打印。打印由用户在可见桌面上用系统自动打印完成；助手不代为绕过系统的缩放与居中。

## 输出

输出工作簿包含：

- `报销单`：纸面打印版和合计公式；
- `发票明细`：来源、页码、票据字段、住宿日期、路线和校验状态；
- `校验与说明`：本地公司资料、规则、待人工确认事项。

同时生成简短校验报告，列出已解析的文件和页码、已确认字段、未解决问题及打印份数。报销单只能在视觉检查通过并明确列出人工复核事项后交付。

模板字段语义见 [references/field-mapping.md](references/field-mapping.md)。
